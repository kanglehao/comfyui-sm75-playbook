## B 组：双卡 H3VM 引擎

**条件**：双 2080 Ti · 736×416 · 124 帧 · 10 步 · `fl2va_pruned_int8_convrot` + turbo8 ×1.0 ·

| 配置 | 分辨率 | 端到端 | 判定 |
|---|---|---|---|
| 双卡 · 单采 · 无 Veda（生产链基线） | 736×416 | **253.4 s / 260.7 s** | 基线 |
| 双卡 · 单采 · Veda 前置 | 736×416 | 240.8 s / 250.7 s | −4~5%，**噪声级** |

| 双卡 · **二采** · 无 Veda | 736×416 | **OOM** | GPU1 余 631 MiB，需 946 MiB |

### 为什么 Veda 的 3.16× 不成立

一句话：**基线选错了。**

A 组的 49.8 s/it 是"单卡 + 稠密注意力"的基线。H3VM 双卡引擎把同一个形状压到 **6.5 s/it**，
这个数字本身已经比 Veda 能达到的水平更低。两个加速叠加时，Veda 没有可压缩的空间。

```
单卡稠密  49.8 s/it  ──Veda──►  15.8 s/it
双卡稠密   6.5 s/it  ──Veda──►  7.9 s/it   ← 反而更慢
```

而且 Veda 的稀疏核在双卡链路上要跑 52.5 s（全片），而整段采样只要约 65 s——
**它自己就不比双卡的稠密注意力便宜多少。**

> 这不是"Veda 不行"，而是"用错了场景"。
> 单卡、无引擎、768×432 左右、8 步——这时候它是神器。
> 一旦上了双卡引擎，注意力已经不是瓶颈了。

## C 组：端到端时间到底花在哪

以 736×416 / 10 步 / 124 帧 / 单段、端到端 253 s 为例：

| 阶段 | 耗时 | 占比 | 还能压吗 |
|---|---|---|---|
| 编码 / 条件准备（首个 s/it 之前） | ~28 s | 11% | 有限，文本编码器加载占大头 |
| 10 步采样 | ~65 s | 26% | 已经很紧，继续压收益 ≤ 20% |
| **VAE 解码 + 音频 + 封装** | **~160 s** | **63%** | **不能，取决于 ComfyUI 支持** |

**这张表是全篇最重要的一张。**

它解释了为什么"再找一个注意力加速器"是错误方向：
即使你让采样时间归零，端到端也只从 253 s 降到 188 s（−26%）。
而 VAE 那 160 秒，目前唯一的希望是 Sol-VAE，它需要 ComfyUI ≥ 0.44。

## 测量方法（这部分比数字更重要）

### 1. 必须换 seed

ComfyUI 有执行缓存。**同 seed + 同参数的第二轮会在 2 秒内返回旧产物**，
日志照样打 `Prompt executed`，产物 MD5 逐字节相同。

如果你只看"跑完了"，会得到一个 100 倍的假加速。

正确的验收：

```bash
# 每轮换 seed，并比对产物
md5sum output/*.mp4
ffprobe -v error -show_entries format=duration -of csv=p=0 output/xxx.mp4
```

**判据：耗时是否真的落在预期量级 + 产物 MD5 是否不同。** 两个都满足才算跑过。

### 2. 多卡引擎不要看 s/it

H3VM 是异步流水，进度条的 s/it 跑在工作前面，会显示一个比真实值更小的数字。
同一配置下 Veda 显示 7.9 s/it、基线显示 6.5 s/it，但端到端是 240.8 vs 253.4 s——
**两个指标方向相反**。只信端到端。

### 3. 每组至少两轮，且交替顺序

"Veda 快了 4%"那组，两次都是 Veda 先跑。
第二轮的模型已热、显存已稳，先跑的那组天然占便宜。交替顺序才能排除。

### 4. 质量不能只看"出片了"

每轮至少检查：

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,sample_rate,channels -of json out.mp4
ffmpeg -i out.mp4 -vf blackdetect=d=0.5:pix_th=0.10 -an -f null - 2>&1 | grep blackdetect
```

- 黑场检测无输出 = 没有黑屏段
- 抽 2 s / 4 s 两帧肉眼对比构图
- 音频轨编码、采样率、声道数一致

稀疏注意力会改变细节（同 seed 下人物姿态、车流位置有轻微差异），
这属于正常的注意力取舍，**不是劣化**——但必须看，不能假设。
